# Coding Standard

## Purpose

Define consistent implementation expectations for Atlas projects.

## Standard

- Follow approved specifications before writing code.
- Keep code simple, readable, and testable.
- Prefer explicit names that reflect the domain language.
- Avoid undocumented behavior and unnecessary abstractions.
- Keep business logic separate from infrastructure details.

## Verification

- Code maps to a specification, story, task, or architectural decision.
- Business rules are covered by tests.
- Reviewers can trace behavior back to documented intent.
