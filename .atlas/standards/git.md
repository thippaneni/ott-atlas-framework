# Git Standard

## Purpose

Keep source history understandable, reviewable, and traceable.

## Standard

- Keep changes focused and easy to review.
- Use clear commit messages that describe intent and impact.
- Do not mix unrelated refactors with feature or fix work.
- Reference specifications, issues, or decisions when relevant.
- Never rewrite shared history without team agreement.

## Verification

- Diffs are scoped to the stated change.
- Reviewers can understand why the change exists.
- Generated or temporary files are excluded unless intentionally tracked.
