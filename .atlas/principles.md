# Atlas Engineering Principles

Atlas principles are immutable engineering rules that apply to every Atlas project.

## 1. Specifications Are The Source Of Truth

Implementation always follows approved specifications. Undocumented functionality must not be generated or implemented.

## 2. Documentation Precedes Implementation

Engineering work starts from documented intent, requirements, architecture, and validation criteria.

## 3. AI Augments Engineering Judgment

AI assists developers and engineering teams. It does not replace human review, decision-making, or accountability.

## 4. Architectural Decisions Must Be Traceable

Every architectural decision must connect to business intent, requirements, constraints, and implementation impact.

## 5. Implementation Must Be Verifiable

Every implementation must be testable, reviewable, and traceable to specifications and acceptance criteria.

## 6. Projects Must Be Reproducible

A project should be understandable and repeatable from its specifications, documentation, architecture, and validation rules.

## 7. Context Must Be Selective

Atlas loads only the context needed for the task. Unrelated modules must not be loaded.

## 8. Extensions Must Preserve Core Behavior

Projects may extend Atlas, but extensions must not modify core Atlas behavior.

## 9. Security By Default

Atlas must never contain passwords, API keys, secrets, certificates, or sensitive credentials.

## 10. Validation Ensures Quality

Specifications define intent. Architecture defines structure. Implementation delivers behavior. Validation ensures quality.
